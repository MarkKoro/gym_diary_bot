# Обучение и выбранная пользователем задача

Обязательная первичная настройка Gym сохраняет прежние native проверки и API.
Переход Core в собственный раздел или возврат не обходят активный onboarding.
Его завершение не является согласием на отложенный переход: после взаимодействия
с настройкой пользователь сам возобновляет выбранную задачу существующим действием.

После успешной native проверки `ProgressorDomain.perform` или `restoreView`
автоматическое необязательное обучение откладывается до конца текущего документа.
Уже активная плашка закрывается до навигации без записи «обучение завершено».
URL-параметр, недействительный/истёкший transfer, другой аккаунт, acting mode,
неверный route/action или устаревшее взаимодействие сами по себе не откладывают tour.
Валидность tab-local transfer, десятиминутный срок и исходный proof по-прежнему
проверяет canonical Core; Gym сохраняет собственные identity/onboarding guards.

Флаг откладывания существует только в памяти документа. Он не пишет localStorage,
не вызывает API, не меняет пользовательский профиль и не считается completion.
Явное «Повторить обучение» вызывает существующий `startTour({force:true})` и
остаётся доступным, включая документ с отложенным автоматическим обучением.
Обязательная настройка блокирует и явный tour, как прежде.

Каждый render шага имеет generation. Stop, новый render и новое обучение
инвалидируют прежнюю подготовку; поздний prepare не возвращает плашку и не
закрывает более новую. После асинхронного cleanup move также перепроверяет
generation перед сменой шага. Нынешние prepare управляют только native UI;
добавление сетевых действий в подготовку требует отдельной отмены их эффектов.

Escape/Back закрывает optional tour без ложной отметки о прохождении. Прежние
явные «Пропустить» и финальное «Закрыть» сохраняют существующий выбор не показывать
автоматическое обучение вновь; owned transition не имитирует эти нажатия.

Проверки `tests/test_optional_tour.cjs` выполняют настоящие shipped функции:
обычный первый вход, automatic timer до/после задачи, explicit repeat, mandatory
onboarding, owner/acting/interaction guards, поздние prepare/cleanup и новое
обучение. Actual HTML/API испытание использует отдельную синтетическую SQLite,
настоящую native/Core аутентификацию и ограниченные faults. Эмуляция браузера
не является проверкой физического Telegram/iOS/Android или human UX uplift.
