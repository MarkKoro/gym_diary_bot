# Проверка качества Gym Diary

Общая [система технических и интерфейсных правил](https://github.com/MarkKoro/progressor_core/blob/main/docs/QUALITY_PROGRAM.md) находится в Core.
Его код не переносится в Gym. Существующие клиенты и canonical helper mirrors
обновляются согласованно; предметной базой и изменениями тренировок владеет Gym.

- GET таблицы упражнений и сводок не создаёт sessions/runs и не удаляет системы.
  Чтение тренером не становится тренировкой ученика. Истечение подписки не удаляет историю.
  Свободная карточка `/all_exercises/exercise/{exercise_id}/session` возвращает
  `session_id=0`, если занятия ещё нет: пустые подходы, `is_done=false`, без черновика бега.
  Первый явный ввод подхода/бега создаёт занятие существующим native writer;
  add_once и его атомарные receipts остаются единственным путём нового versioned подхода.
  Legacy bootstrap владельца/пустой системы и числовой user_exercise alias сохраняются:
  это ограниченная гарантия про sessions/runs, не обещание полной SQL-чистоты всех GET.
  Отмена карточки не добавляет подход, занятие или черновик; сохранённые заметки и история
  читаются независимо от наличия занятия. Изменение alias/bootstrap требует отдельного API/UI контракта.
- Предыдущая тренировка выбирается по владельцу, системе, дню и выполненным подходам
  до загрузки её подходов. Пустая или содержащая только разминку более новая сессия
  не подменяет предыдущий результат. Проверяйте разные user_exercise aliases.
- Настройка частоты не вызывает очистку старых систем. Замена касается только
  подтверждённой активной системы. Некорректная частота отклоняется без записи.
- Платежи, подписка и referral принадлежат личному аккаунту. Acting/trainer mode
  не предоставляет эти возможности от имени подопечного.
- Личные названия измерений и заметки не становятся общим каталогом.
  Явные инструкции в опубликованной системе и личные заметки — разные поля.
  Собственное клонирование не удваивает заметку.
- Пользовательские подписи и результат ИИ передаются в текст/безопасные атрибуты:
  публичный день/система, настройки дня, измерение, AI decision buttons.
- Reminder всегда проверяет текущего владельца Telegram destination. Поздний
  callback или отозванная тренерская связь не меняют чужой чат.
- Оба экрана упражнений и свободная тренировка сохраняют собственные факты;
  агрегат не считает пустые/черновые занятия завершёнными. Силовые и бег сохраняются.
- Закрытое меню и неактивный confirmation overlay скрыты для клавиатуры. Активное
  окно удерживает фокус; Back/Escape закрывает или отменяет верхнее окно, сохраняя маршрут.
  На 200% тексте заголовок и кнопки растут, области касания остаются доступны.

Запускайте Linux unittest и четыре существующих pytest функции на временных базах,
без второго consumer. Для DOM используйте настоящий `webapp/index.html` с fake SDK.
Проверяйте `test_quality_reads`, `test_quality_native_scope`, заметки, подписки,
свободные/плановые занятия и напоминания. Зависимости устанавливаются из
`requirements.txt` с `constraints.txt` в отдельное окружение.


## Независимый запуск общего интерфейса

Локальный `webapp/assets/progressor-bootstrap.v1.js` — точная distribution copy канонического `Core/shared/bootstrap.v1.js`. Он захватывает исходный Telegram launch и не заставляет собственные запросы бота ждать Core. Общий UI по-прежнему загружается из единственного Core асинхронно; backend Core в бот не копируется. При правке bridge обновляйте canonical и все три копии вместе: update-all сверяет байты. При cross-navigation SDK может возвращать обновлённый proof исходного бота; не переименовывайте его источник в текущий продукт. Если sessionStorage недоступен, собственный бот работает, а неподтверждённый переход не выполняется.


Payment menu consistency: three primary periods (1/6/12 months), equal RUB/Stars buttons per row, retained extra periods with a return action. Existing quotes, SKUs, receipts, native expiry and provider confirmation are unchanged. Canonical progressor_bot.py must match Core shared/progressor_bot.py. Food menus read current billing settings. Legacy callback names remain compatible.
